# BigBrain 0.2.0

This cleanup release makes persistence and replay reliable, reduces
backlog work, and clarifies the engine's internal contracts.

- Concurrent writers cannot overwrite an immutable event. Identical
  retries deduplicate; conflicting bytes for the same event are refused.
- Revocations resolve by `(created_at, id)` in both direct log reads and
  projections. Rebuilding the index preserves the same result regardless
  of the order events arrived.
- Memory checkpoints record observed event IDs. Backdated corrections,
  withdrawals, and entity aliases now make memory due on its normal
  schedule. Successful runs retain their checkpoint and schedule in the
  run journal, so deleting or corrupting the cached stamp cannot disable
  an established schedule. Failed attempts retain their retry interval.
- Pending email and its polling checkpoint live in durable, gitignored
  `.spool/`. Backlog listings read small headers without parsing message
  bodies or attachments. Admission and passing persist their outcome
  before removing the pending data.
- Intake priorities are indexed. Counts and batch limits execute in SQL
  without loading and sorting the entire backlog in JavaScript.
- Internal intake receipts always name the stored insertion. Compatibility
  labels for older HTTP clients are isolated at the boundary. The path
  access module is now named `browsePaths` for its actual responsibility.
- The engine has a clean, scoped TypeScript check enforced in CI. This
  also fixes the missing prompt-cleanup import in `bigbrain install` and
  removes obsolete types, parameters, and comments along these paths.

Existing event logs and curated content are read in place. The derived
projection database rebuilds automatically. A memory schedule created by
an older engine reconciles the current record once at its next scheduled
run, then uses exact checkpoints.

Older staged files and email state are preserved on first access by the
updated engine; allow it to access staging or poll email before deleting
an older `.state/` directory. Include `.spool/`, `.blobs/`, and local
credentials in file backups alongside the git record. See
[the backup instructions](../self-host.md#backup).
