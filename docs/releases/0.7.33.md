# BigBrain 0.7.33

- Reviewing an inclusion rule now suggests sources that actually fit it. A rule like "things about our will, shared with @Someone" used to surface anything mentioning that person, because "will" was ignored and the person was taken as the topic. One Quick call per rule now turns it into search phrases (estate plan, executor, guardian…) and tells the audience apart from the subject before any source is scored; if that call fails, the rule's own words rank as before.
- Shared vaults can be added to Claude (Desktop, web and mobile) as a read-only custom connector: paste `https://<server>/mcp` into Claude's Settings → Connectors and sign in with an invite link. Claude can search and read the vault; it cannot change anything. The server operator turns this on with `--public-url`; it is off otherwise (`docs/shared-vault-connector.md`).
- An invite link opened in a browser now explains how to join in Claude and in the BigBrain app, and names the vault only while the link is still valid. A used or expired link says so.
- Pasting a vault's join link into Connect vault is refused with a message saying to open it in a browser first.
- For servers configured with Google sign-in, the Members screen invites by email, and members get a join link and a personal page for connecting more devices. Real Google sign-in has not yet been tested.

Verification: the full engine suite passes. The new inclusion ranking was tried on a real vault in the browser, where a will-and-estate rule's first suggestions became trust, executor and financial-planning notes instead of unrelated ones. The connector was exercised end to end against Claude Desktop through a public tunnel. Claude Desktop's first request on each connection names an MCP protocol version the SDK does not yet support; it is refused and Claude falls back on its own.
