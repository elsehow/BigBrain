## The claim under test

The founding principle says the vault is a *pure derived view* of the lake.
The vault already records everything that claim needs to be tested
mechanically: absorption is verified by `sources:` citations in the staged
diff (lib/editor/outcomes.ts), every processed ref carries a stated outcome
in the run journal's report block, and directives ride the queue as data.
So the test is: rebuild the queryable surface from `references/` plus the
recorded decisions — no model — and measure what breaks and what the model
was actually buying.

**Corpus.** A read-only clone of Nick's prod vault (the bench's established
`--corpus <vault-clone>` pattern). At clone time (2026-08-14): 645
references, 222 entities, 316 run records carrying 428 stated outcomes
(233 absorbed / 190 declined / 5 tended), 685 settled queue messages, 17
failed, and a retrieval ledger of 83 searches + 1,001 uses — the query log
the compiled surface is scored against. Baseline on the curated surface:
41% search→open, MRR 0.30.

## Phases and gates

**Phase 1 — the re-derivability audit (`bigbrain compile --check`, zero
LLM).** Mechanical scan of corpus invariants: every entity log entry cites a
source; every cited source exists in the lake; every landed ref has a
settled outcome; every entity is reachable from some absorbed ref. Output:
a derivability percentage plus a violation list, per stratum (import era vs
contract era). This alone is a result — it converts the founding principle
from doctrine to measurement, and its violation list defines the compiler's
real input contract (e.g. whether the import stratum needs its own source
treatment).

**Phase 2 — the zero-LLM compile (`bigbrain compile --out <dir>`).**
Rebuild the surface bottom-up through the three cost layers:

1. *Mechanical layer* — search index and link graph: existing deterministic
   code pointed at the output.
2. *Decision replay* — resolve via the alias matcher (stages.ts's
   deterministic tier), judge/place/absorption read from the journal and the
   `sources:` citations rather than re-asked. No recorded decision → the
   item is flagged `unresolved`, never guessed.
3. *Skeleton synthesis* — per-entity dossiers assembled deterministically:
   aliases, wikilinks, and a chronological source log from envelope
   titles/dates and the discussable versions the integrations delivered.
   Structure without prose.

Gates: **determinism** (compile twice → byte-identical) and **coverage**
(every absorbed ref lands in at least one compiled dossier).

**Phase 3 — score against the real query ledger.** Replay the corpus's
recorded searches against the compiled surface's index; attribute the
ledger's recorded uses; compare hit rate and MRR to the curated baseline.
The headline number is the retrieval gap between a $0 skeleton surface and
the LLM-curated vault, measured on real queries — i.e. what the synthesis
spend actually buys at retrieval time. Both outcomes are decisive: parity
means prose synthesis is mostly human-facing polish (95% of this vault's
reads are agents), so heat-weighted synthesis (#325) becomes pure savings;
a collapse locates and prices the load-bearing synthesis.

**Phase 4 — priced residues (gated on Phase 3's miss map).** Re-admit
models only where misses cluster, in ascending cost: haiku on the matcher's
ambiguous residue (~cents), judge only for unjournaled items, prose
synthesis only for heat-hot entities (materialize-on-miss, #326, applied at
compile time). Each addition re-scored by the same replay:
retrieval-delta-per-dollar. Worst case — full cold compile, all staged
models — is ≈ $5.30/100 items by the intake-decomposition table; this plan
spends $0 through Phase 3.

## Constraints

All laptop-local against the disposable clone: no prod risk, no deploys,
the prod freeze untouched, the tenant meter untouched. Any Phase-4 calls go
through `queue.engine: claude-cli` on max auth, the bench's path. The
corpus clone never receives writes; compile output goes to `--out`.

## Non-goals

Replacing the editor. The compiler is an instrument first: it measures
where synthesis earns its cost. Live pipeline changes stay with the
intake-decomposition milestone and its shadow/flip gates.

## Work breakdown

1. `compile --check`: corpus invariant audit + per-stratum report. (M)
2. `compile --out`: mechanical index + decision replay + skeleton
   dossiers; determinism and coverage gates. (M)
3. Replay scorer: ledger searches against a compiled surface, hit/MRR
   vs baseline, miss map. (S)
4. Priced residues, heat-weighted (gated on 3's miss map). (M)
